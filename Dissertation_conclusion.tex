\chapter{Conclusions}
\label{chapter:conclusion}

This dissertation investigates how to address DRAM capacity limitations and improve DRAM utilization in data-intensive JVM applications.
We demonstrate how storage-backed managed heaps can extend heap capacity beyond DRAM while reducing serialization and deserialization (S/D) overhead and expensive garbage collection (GC) operations over storage.
We further show how I/O-aware dynamic heap resizing can improve DRAM utilization by balancing GC overhead against the cost of accessing data through the operating system (OS) page cache.
Together, these contributions address three complementary challenges: managing storage-resident objects without full GC scans, supporting object migration in low-pause collectors, and dynamically allocating DRAM between the JVM heap and the I/O cache.

First, we introduce TeraHeap, a storage-backed heap for throughput-oriented applications that combines a DRAM heap (DH) with a region-based storage-backed heap (SH) memory-mapped over fast storage.
TeraHeap preserves direct access to Java objects without S/D and uses framework hints to identify objects suitable for migration to SH.
To avoid expensive GC operations over storage, it tracks cross-heap references and dependencies among SH regions, allowing the collector to manage storage-resident objects without scanning the entire SH.
Region-level reclamation further reduces GC-induced I/O by avoiding object compaction on storage, trading additional storage capacity for lower reclamation overhead.
Our evaluation demonstrates that TeraHeap improves application performance in the studied analytics and graph-processing workloads by reducing memory pressure, GC overhead, and data-conversion costs.

Next, we introduce Chipper, which extends storage-backed heap management to low-pause garbage collectors and latency-sensitive applications.
Unlike throughput-oriented collection, low-pause collection must account for the additional cost of migrating live objects to storage when selecting regions for incremental GC.
Chipper extends the collector's region-selection model to consider both migration costs and the DRAM recovered through garbage reclamation and object migration.
It further integrates migration into parallel evacuation and provides a separate path for migrating large objects during full GC.
Our evaluation demonstrates that these mechanisms reduce application tail latency compared with DRAM-limited on-heap caches, storage-backed off-heap caches, and the throughput-oriented storage-backed design in the studied workloads.
These results show that extending managed heap capacity beyond DRAM in latency-sensitive applications requires storage-aware migration policies that account for the collector's pause-time constraints.

Finally, we introduce FlexHeap, an I/O-aware dynamic heap-resizing mechanism that improves DRAM utilization by adapting the division of physical memory between the JVM heap and the I/O cache.
FlexHeap estimates the time lost to GC and I/O stalls and uses their combined cost to determine when and by how much to resize the JVM heap.
By accounting for both costs, FlexHeap adapts to changes in application memory and I/O demands rather than relying solely on GC-driven resizing decisions.
Our evaluation demonstrates performance improvements in the studied search and analytics workloads compared with existing heap-resizing policies.
Although FlexHeap does not require a storage-backed managed heap, it provides a complementary approach to improving DRAM utilization that could also benefit storage-backed heap designs.

Together, these contributions demonstrate that efficient JVM memory management requires addressing both managed heap capacity and the utilization of available DRAM.
TeraHeap and Chipper show that extending the managed heap to storage requires controlling GC-induced I/O and adapting object migration to different collection objectives.
FlexHeap shows that managing DRAM effectively also requires considering the interaction between GC overhead and storage I/O rather than optimizing GC in isolation.
The broader insight of this dissertation is that managed runtimes should account for storage-access and data-movement costs when deciding where objects reside, how they are collected, and how physical memory is allocated.
